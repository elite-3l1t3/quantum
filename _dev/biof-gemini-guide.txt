BIOF.SITE — ТӨСЛИЙН БҮРЭН ТАЙЛБАР (Gemini-д зориулав)
=====================================================
Хэрэглэгч Монгол хэлээр ярьдаг. Хариултаа Монголоор өг. UI-ийн бүх текст Монгол.

1. ТӨСӨЛ
-------
biof нь guns.lol / noiz.bio төрлийн "bio-link" вэбсайт. Хэрэглэгч biof.site/username хаягаар өөрийн хуудастай болно (линк, avatar, background зураг/видео, дуу, badge, view, like).
- Зөвхөн Discord-оор нэвтэрнэ.
- Хамгийн эхэнд бүртгүүлсэн хүн автоматаар ADMIN (#1). Хүн бүр bid (#1, #2, #3...) дугаартай.
- Одоо WAITLIST горимд: эхний хэрэглэгчээс бусад нь зөвхөн username нөөцөлнө. Admin "release" хийх хүртэл тэдний хуудас нийтэд харагдахгүй, тохиргоо хийж чадахгүй.
- Leaderboard ХАСАГДСАН.
- /a хаяг нь TEMPLATE (жишээ профайл, өгөгдөлгүй, кодод DEMO объектоор тодорхойлогдсон).
- Үйлчилгээний нөхцөл (/tos), Нууцлалын бодлого (/privacy) хуудастай.
- Өнгөний загвар: шар-бор (amber/хүрэн), хөнгөн, lag-гүй, утас + компьютер дээр ажиллана.

3. ФАЙЛУУД (GitHub repo-гийн үндсэн хавтсанд)
--------------------------------------------
Frontend:
- index.html       Нүүр хуудас shell (<body data-p="home">)
- settings.html    Тохиргоо (data-p="settings")
- admin.html       Admin самбар (data-p="admin")
- 404.html         Профайл хуудас БА 404 (data-p="profile"). GitHub Pages үл мэдэгдэх замд 404.html үйлчилдэг тул biof.site/username энд ажиллана.
- tos.html, privacy.html   Хууль, нөхцөл (data-p="doc"; агуулга нь шууд HTML дотор, app.js нь цэс+footer нэмнэ)
- style.css        Бүх хуудсанд нийтлэг загвар
- app.js           Бүх логик (нэг файл)
Бүх shell нь: <div id="app"></div> + supabase CDN script + /app.js + /style.css.
Extensionless URL (/settings, /admin, /tos, /privacy) GitHub Pages-д .html руу автоматаар зүүгдэнэ.
- CNAME            Агуулга: biof.site

SQL (Supabase SQL Editor дээр ажиллуулах):
- schema.sql       ХУУЧИН суурь (хүснэгт, RLS, функц). Нэг л удаа. Дахин ажиллуулбал "relation already exists" алдаа гарна.
- update.sql       theme багана, ensure_profile, claim_username, хуучин хэрэглэгчдийн профайл backfill
- storage.sql      'media' bucket + upload policy, reserved: index, 404
- waitlist.sql     approved багана, site хүснэгт, site_stats, шинэчилсэн handle_new_user / ensure_profile / admin_act / RLS
Дараалал: schema.sql → update.sql → storage.sql → waitlist.sql (бүгд update/waitlist/storage нь давтаж ажиллуулж болно).
Бүгдийг цэвэрлэх бол: drop table if exists vlog, likes, reserved, profile_private, profiles, site cascade; (auth.users доторх хэрэглэгчийг ч устга, эс бөгөөс #1 admin дахин тогтохгүй).

4. ROUTING
----------
- body[data-p] нь хуудасны төрлийг заана: home | settings | admin | profile | doc.
- Профайл: замаас (location.pathname) username-ийг авна (жижиг үсэг, .html-ийг тайлна).
- /a → DEMO template (DB-гүй; like локал, view тоологдохгүй; "Өөрийн хуудсаа үүсгэх" товч).
- Олдохгүй профайл → nf() 404 хуудас (боломжтой нэр бол "Энэ нэрийг авах" товчтой).
- Reserved username (авч болохгүй): admin, login, settings, leaderboard, api, biof, www, help, support, terms, index, 404, a, tos, privacy + admin-ы нэмсэн.
- Username дүрэм: ^[a-z0-9_]{2,20}$

5. app.js БҮТЭЦ
---------------
Тогтмол/туслах: SB_URL, SB_KEY, sb (supabase client), $ (querySelector), e (HTML escape), safe(url) (http/https шалгах), cu(url) (CSS url-д аюулгүй эсэх), av(p) (avatar эсвэл эхний үсэгтэй дугуй), bdg(p) (badge жагсаалт), BR/bc (линкийн брэнд өнгө: instagram, tiktok, youtube, x, github, discord, twitch, spotify, telegram, facebook, snapchat), ERR (алдааны мессеж), toast() (давхардал шалгана), global error/unhandledrejection → toast.
Төлөв: me (өөрийн profiles мөр), user (auth user), aud (дуу Audio объект).
Функцүүд:
- loadMe(): session авна, ensure_profile RPC дуудна, profiles-ээс өөрийн мөрийг уншина; localStorage.pending username байвал claim_username дуудна.
- bar(): дээд цэс (biof, Template, Admin (admin бол), #bid username эсвэл "Discord-оор нэвтрэх"), ban мэдэгдэл.
- doRoute()/route(): нэг нэгээр дараалуулсан (Promise chain) — давхар зурагдахаас сэргийлнэ. Skeleton карт харуулаад хуудсаа зурна. Footer (/tos, /privacy).
- home(v): hero (Waitlist/Нээлттэй pill, username claim бар, live шалгалт), preview карт, marquee, features, алхмууд, FAQ, CTA. Reveal-on-scroll (IntersectionObserver). site_stats RPC-ээс тоо авна.
- nf(v,name): 404.
- profile(v,name): карт, avatar, нэр, @username · #bid · байршил, badge, bio (typewriter сонголттой), линкүүд, view/like/хуулах, дуу удирдлага (play/pause + volume), click-to-enter overlay, background зураг/видео. Өнгө (accent, текст), card opacity, булан radius theme-ээс. add_view RPC (өөрийн хуудас болон demo-д тоолохгүй).
- shrink(file,max) / up(kind,file): зургийг canvas-аар жижигрүүлж webp болгоно (avatar 512px, bg 1920px; gif хэвээр), Supabase Storage 'media' bucket-д {uid}/{avatar|bg|video|music}.{ext} замаар upsert, public URL + ?v=timestamp буцаана. Хязгаар: зураг 12MB (оролт), видео 15MB (mp4/webm), дуу 10MB.
- settings(v): waitlist-д байвал зөвхөн төлөвийн карт. Үгүй бол 4 tab: Профайл (username, нэр, bio, байршил, click-to-enter текст), Төрх (accent, текст өнгө, opacity, radius, typewriter, "Template ашиглах"), Медиа (avatar, bg, видео, дууг файлаар оруулах), Линк (мөр бүр "Нэр | https://url", дээд тал нь 12). Хадгалах → profiles update.
- admin(v): admin-д л. Хэрэглэгчийн жагсаалт (500 хүртэл), хайлт (username/#bid), товчнууд: Approve, Ban/Unban, Нэр солих, Free (username-ийг сул болгох), Badge. Дээд хэсэгт: "Site release (бүгдийг нээх)", "Waitlist болгох", username Taken (reserve) / Available (release).
- onAuthStateChange: бэлэн болсны дараа хэрэглэгч солигдвол loadMe + route.
- localStorage: pending (нэвтрэхээс өмнө сонгосон username), vid (view давхардал шалгах санамсаргүй ID), Supabase session.

6. ӨГӨГДЛИЙН САН (Supabase Postgres)
----------------------------------
profiles: id (uuid, auth.users), bid (int unique, gapless: max+1 advisory lock), username (unique, nullable), display_name, bio, avatar_url, bg_url, accent (#hex, default #e8a317), links (jsonb [{label,url}]), badges (text[] — admin өгсөн), role ('user'|'admin'), banned, views, likes, username_changed_at, created_at, theme (jsonb), approved (boolean).
theme jsonb түлхүүрүүд: loc, enter, video, music, tc (текст өнгө), op (opacity 0.3-1), r (radius 0-40), tw (typewriter boolean).
profile_private: id, discord_id, discord_name, ban_reason (зөвхөн эзэн + admin харна).
reserved: username (admin нөөцөлсөн / системийн), note.
likes: (profile_id, user_id) PK.
vlog: (profile_id, visitor, at) PK — view давхардал (6 цагт 1).
site: id=1, open boolean (waitlist нээлттэй эсэх).
Storage: bucket 'media' (public, 15MB). Policy: бүгд унших; зөвхөн өөрийн {uid}/ хавтсанд insert/update/delete.

Trigger: on_signup (auth.users insert) → handle_new_user(): bid олгоно, эхний хэрэглэгч role='admin' + approved=true, бусад approved = site.open.
Функцүүд (бүгд security definer):
- is_admin()
- ensure_profile(): auth user-д профайл байхгүй бол үүсгэнэ (schema-аас өмнө бүртгүүлсэн хэрэглэгчийн засвар)
- username_status(u) → 'available'|'taken'|'invalid'
- claim_username(u) → 'ok'|'taken'|'invalid'|'cooldown' (өөрчлөлт 7 хоногт 1, admin үл хамаарна)|'banned'
- add_view(pid, v), toggle_like(pid) → true/false/null
- site_stats() → {open, waiting, live}
- admin_act(act, target(bid), val): ban, unban, rename, free, badges (таслалаар), approve, reserve (val=username), release (val=username; эзэмшигчээс нь авна), open (site нээх + бүгдийг approve), close.
RLS:
- profiles SELECT: (username not null AND not banned AND approved) OR өөрийн мөр OR admin. UPDATE: өөрийн мөр AND not banned AND approved; зөвхөн багана: display_name, bio, avatar_url, bg_url, accent, links, theme (role, bid, views, likes, banned, badges, username, approved-г зөвхөн RPC өөрчилнө).
- profile_private SELECT: эзэн/admin. likes SELECT: өөрийн. site SELECT: бүгд. reserved, vlog: шууд хандалтгүй (RPC-ээр).
Автомат badge (кодод тооцоолно): Admin, OG (bid ≤ 100), 1K+ views, 50+ likes; нэмээд profiles.badges.

9. ӨМНӨ ЗАСАГДСАН АЛДААНУУД (дахин гаргахгүй байх)
-----------------------------------------------
- "Cannot set properties of null (setting 'textContent')" spam: нэвтэрсэн үед route() давхар ажиллаж typewriter interval устсан элемент руу бичдэг байсан. Засвар: route-ыг дараалуулсан, давхар trigger-ийг арилгасан, интервал isConnected шалгана, toast давхардал шалгана.
- Хуучин бүртгэлтэй хэрэглэгчид профайлгүй (trigger дараа нэмэгдсэн) → ensure_profile + backfill.
- "relation profiles already exists": schema.sql-ийг дахин ажиллуулсан. Үүний оронд update/waitlist/storage.sql ашигла.
- Товчны текст хоёр мөр болох → button{white-space:nowrap}.

- js/core.js     тохиргоо, sb client, туслах функцүүд (e, safe, cu, av, bdg, bc), toast, DEMO, loadMe, bar, .lg (login) товчны click delegation

Хуудас бүр зөвхөн хэрэгтэй script-ээ ачаална: core → (хуудасны script-үүд) → main. Cache-bust: ?v=2 (шинэчлэх бүрд тоог нэм).

АЮУЛГҮЙ БАЙДАЛ
- Хуудас бүрт Content-Security-Policy meta: script зөвхөн self + cdn.jsdelivr.net; connect зөвхөн Supabase + api.lanyard.rest; img/media зөвхөн self, Supabase Storage, cdn.discordapp.com. Inline onclick ашиглахгүй (class="lg" + delegation). Шинэ гадаад домайн хэрэгтэй бол meta CSP-ийг БҮХ html-д засна.
- cu(): avatar/bg/video/music URL зөвхөн манай Storage (…/storage/v1/object/public/media/) эсвэл Discord CDN. DB-д мөн CHECK constraint c_media.
- DB: c_len constraint (bio≤200, нэр≤40, линк≤12, theme/links<4KB). anon-д admin_act, claim_username, ensure_profile, toggle_like, set_presence EXECUTE эрх хураасан (v2.sql).
- Like: зөвхөн approved, ban-гүй хэрэглэгч. View: минутад профайл бүрт 30-аас ихгүй, 6 цагт 1 visitor-д 1.
SUPABASE FREE QUOTA
- Storage: bucket лимит 8MB, mime шүүлтүүр; клиент: зураг ≤12MB (webp болгож жижигрүүлнэ), видео ≤8MB, дуу ≤5MB; cacheControl 1 жил (?v=timestamp-аар шинэчлэгдэнэ) → egress бага.
- vlog хуучин мөрийг (>1 өдөр) санамсаргүй цэвэрлэнэ.
- Клиент талд: ensure_profile зөвхөн профайл байхгүй үед; site_stats 60 сек sessionStorage cache; view RPC-г 6 цагт 1 удаа (localStorage v_<profileId>); realtime ашиглахгүй.
- Supabase Dashboard дээр хий: Authentication → Providers → Email-ийг унтраа, "Allow anonymous sign-ins" унтраа (зөвхөн Discord үлдээ). Authentication → Rate Limits-ийг шалга.
ШИНЭ FEATURE (guns.lol шиг)
- theme jsonb нэмэлт түлхүүр: sh (avatar хэлбэр circle|round|square), fx (нэрний эффект none|glow|sparkle), ls (линкийн загвар fill|outline|pill), tl (3D tilt, зөвхөн hover төхөөрөмж).
- Discord presence: profiles.presence_id (opt-in; set_presence RPC). Профайл дээр api.lanyard.rest-аас online/idle/dnd/offline + идэвхтэй үйл ажиллагаа харуулна. Хэрэглэгч discord.gg/lanyard серверт нэгдсэн байх ёстой.
SQL ДАРААЛАЛ: schema → update → storage → waitlist → v2.sql.
